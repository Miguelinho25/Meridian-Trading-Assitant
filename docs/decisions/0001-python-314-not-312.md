# ADR-0001 — Python 3.14.6 instead of 3.12

**Status:** Accepted · **Date:** 2026-07-27

## Context

The brief specifies Python 3.12. The machine has Python 3.14.6 (Homebrew) and no 3.12.
A new major Python often lacks wheels for the scientific stack, which would be a real
reason to install 3.12.

## Evidence

Rather than assume, I built a throwaway venv on 3.14.6 and installed the full stack.
All resolved and imported cleanly:

```
numpy 2.5.1        pandas 3.0.5       scipy 1.18.0
sklearn 1.9.0      statsmodels 0.14.6 fastapi 0.140.1
pydantic 2.13.4    sqlalchemy 2.0.51  alembic 1.18.5
pytest 9.1.1       sqlite3 3.53.3
```

## Decision

Target Python 3.14.6. `requires-python = ">=3.12"` so the project remains
3.12-compatible for anyone else.

## Consequences

- Avoids installing a second interpreter for no measurable benefit.
- 3.14's improved error messages and free-threading work are incidental gains.
- **Risk:** a future dependency may lag on 3.14. Mitigated by keeping the floor at 3.12
  — dropping back is an interpreter switch, not a code change.
- Polars is deferred; pandas 3.0 covers current needs and is the better-tested path.
